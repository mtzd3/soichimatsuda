# 11. Lecture Deck System

## 1. Purpose

KairosAIの複雑な戦略を、結論だけでなく「なぜそうなるか」まで順番に理解できる資料へ変換する。

想定読者は、AI・半導体・データ主権の専門知識が必ずしも揃っていない政策担当者、経営者、事業責任者である。

## 2. Reference pattern

経済産業省の事務局説明資料に見られる以下の説明構造を参照する。

1. 問題意識を共有する
2. 環境・競争条件の変化を説明する
3. 変化がどの課題を生むかを因果で示す
4. 現状と目標状態を対比する
5. 目標へ至る政策・実装手段を分解する
6. ロジックモデルと指標で検証可能にする

参照するのは説明構造であり、配色や様式をそのまま模倣しない。

## 3. Core rule: one causal relation per slide

各ページは原則として以下の一つだけを説明する。

```text
前提 / 原因
  ↓
変化する仕組み
  ↓
直接の結果
  ↓
戦略上の意味
```

因果が5段階を超える場合は、全体図を先に置き、その後1〜2段階ずつ解説する。

## 4. Standard lecture sequence

各章は次の順序で構成する。

1. `QUESTION`: この章で答える問い
2. `OVERVIEW`: 因果の全体像
3. `CAUSE`: 原因を一つずつ説明
4. `MECHANISM`: 何が媒介するかを説明
5. `RESULT`: 直接・間接の帰結を分ける
6. `IMPLICATION`: KairosAIの判断へ接続する

## 5. Slide grammar

### L01 Question

- 章で答える問い
- 読み手が既に知っている前提
- 答えの方向性

### L02 Causal chain

- 3〜5個のノード
- 矢印上に動詞または条件を置く
- 最終ノードだけを強調する

### L03 Cause and consequence

- 左: 原因・前提
- 中央: 作用する仕組み
- 右: 結果
- 下: 戦略上の意味

### L04 Step explanation

- 左上にステップ番号
- 主語＋動詞の見出し
- 「なぜ」「何が残るか」の二段説明

### L05 Current / Target

- 現状と目標を同じ評価軸で比較
- 中央に「変える手段」
- 目標状態を願望ではなく検証可能な能力で書く

### L06 Logic model

```text
Input → Activity → Output → Outcome → Impact
```

- 各段階の混同を避ける
- KPIを対応する段階へ配置する
- 反証条件を併記する

## 6. Visual rules

- 背景は `#FAF9F7`
- タイトルは黒、30pt前後
- 大見出し帯は濃紺 `#173B6C`
- 因果の主要矢印は濃紺
- 判断・重要な転換点はオレンジ `#E45B1B`
- リスクや失われるものは赤 `#A43E3E`
- 実行・継続能力は緑 `#637A68`
- 本文は17〜19pt
- 1枚のノードは最大5個
- 矢印だけで因果を主張せず、矢印の上に作用を短く記す

## 7. Evidence labels

- `FACT`: 公的資料・一次資料で確認
- `HYPOTHESIS`: Pilotで検証
- `INFERENCE`: KairosAIの戦略的推論
- `GATE`: 継続・分岐の判断条件

## 8. Quality questions

1. 原因と結果の間に説明されていない飛躍がないか
2. 必要条件と十分条件を混同していないか
3. 時系列と階層を同じ図へ混ぜていないか
4. 事実とKairosAIの推論が区別されているか
5. このページを読んだ人が、次のページを必要とする理由が明確か
