# 06. Writing System

## 1. Tone

KairosAIの文体は次を満たす。

- 断定的だが誇張しない
- 技術的だが専門用語へ逃げない
- 政策的だが抽象論で終わらない
- 前向きだがリスクを隠さない

## 2. Action title

タイトルは20〜45文字を目安とし、一文で結論を書く。

推奨パターン:

- `XではなくYが必要である`
- `Xを先行させることでYを実現する`
- `Xが成立する条件はA・B・Cである`
- `Xを放置するとYを失う`
- `Phase 1ではXを検証し、Phase 2の投資判断へつなげる`

避ける:

- 名詞だけ
- 疑問形だけ
- 「〜について」
- 「概要」
- 「検討」
- タイトル内の過剰な括弧

## 3. Lead

Leadはタイトルを支える前提または読み方を書く。

良いLead:

> 保存場所だけでは改善能力は守れない。評価、配備、停止、移行を国内で実行できることが条件になる。

悪いLead:

> 本スライドでは改善能力について説明する。

## 4. Body copy

- 一文は60文字以内を目安
- 一段落は3文以内
- 箇条書きは最大5点
- 箇条書きは文法を揃える
- 主語を省略しすぎない
- 「こと」「もの」「実施する」を減らす

## 5. Bullet grammar

同一リスト内では形式を統一する。

動作:

- 評価する
- 配備する
- 停止する

名詞:

- 評価基盤
- 配備権
- 停止条件

動作と名詞を混在させない。

## 6. Executive language

曖昧:

> 検討を進める必要がある

明確:

> 2026年Q3までにPhase 1の調達可否を決定する

曖昧:

> 連携が重要

明確:

> 政府調達、電力契約、モデル評価を同一ゲートで管理する

## 7. Claims

強い表現には強い根拠が必要。

| 表現 | 必要な根拠 |
| --- | --- |
| 必ず、唯一、不可欠 | 複数の一次根拠または論理証明 |
| 可能性が高い | 比較データまたは検証 |
| 有望 | 仮説と評価軸 |
| 必要 | 条件と不採用時の影響 |
| 最適 | 比較対象と目的関数 |

## 8. Japanese / English

- 日本語の中で英語を乱用しない
- 初出時に日本語または定義を添える
- product / model / policy等の表記をデッキ内で統一
- `/`の多用を避ける
- 英数字の前後に不自然な空白を入れない

## 9. Labels

ラベルは短くする。

- `Current`
- `Target`
- `Risk`
- `Gate`
- `Owner`
- `Decision`

ラベルを長文の見出しとして使わない。

## 10. Editing test

各文に対して問う。

1. 誰が
2. 何を
3. なぜ
4. いつまでに
5. 何をもって完了とするか

必要な情報がない場合は、文を強く見せる前に内容を補う。
