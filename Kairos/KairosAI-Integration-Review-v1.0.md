# KairosAI 文書統合レビュー v1.0

> 基準日: 2026-06-19  
> 対象: 指定された7文書  
> 結果: `KairosAI-Canonical-Master-v1.0.md` を正本として新設

---

## 1. 総評

七文書の戦略的な中心命題は、おおむね一致している。

- 汎用巨大モデルの正面追随を出発点にしない
- 重点領域の現場導入を先行する
- 保存場所だけでなく学習・更新・実行の権利を守る
- 柱A/B/Cを同時並行で進める
- GPU先行でソフトウェアと運用知見を作る
- 実行基盤を国内で持つ
- 汎用化・専用HWは条件付きで進める

一方、改訂時期と用途が異なる文書が並存した結果、実装レベルでは複数の衝突が生じていた。

最大の問題は、**戦略原則、技術仮説、事業仮説、政策メッセージが同じ強さで書かれていたこと**である。このため、後の文書が前の文書を更新したのか、別用途として補足しただけなのかが判別しにくくなっていた。

正本では次を行った。

1. 戦略原則と計画仮説を分離
2. 同じ語の複数定義を解消
3. 適用スコープの違いとして両立できる主張を統合
4. 固定すべきでない技術・法人・規模をゲート付き選択肢へ変更
5. 文書の正準順位を新設

## 2. 主要な不整合と統合判断

| 論点 | 衝突していた記述 | 正本での判断 |
| --- | --- | --- |
| 電力 | 「調達ではなく効率で解く」対「電力主権として長期確保」 | Site Computeは効率、Shared Sovereign Computeは量・立地・電源を確保 |
| GPU規模 | 顧客オンプレ1〜32+ GPU対、500〜10,000 GPUのPhase表 | Site ComputeとShared Sovereign Computeを別スコープ化 |
| Phase数 | 3 Phaseと4 Phaseが混在 | 実行は4 Phase。3区分は政策時間帯として分離 |
| Phase期間 | 18〜48か月、18〜36か月、暦年2026〜35が混在 | T0基準の0〜18、18〜36、36〜60、60か月以降へ統一 |
| SPC | v2.21では事業創出機構を除去した一方、実装文書では正本由来としてSPCを詳述 | SPCは任意の案件・資金ビークル。戦略の必須構成から外す |
| 公共層と営利層 | L1公共保有、L2〜L4顧客所有を固定 | 所有を一律固定しない。顧客主権資産と共有可能資産で判定 |
| Layer 1 | 基盤モデル、顧客資産、短期事業の三つの意味 | 「Model Layer L1」以外ではLayer番号を使わない |
| A→B→C | 一方向の因果連鎖と、同時並行・A/C共同生産が併存 | 説明順はA/B/C、現場ではA+C共同導入、Bが支援 |
| 原本データ | KairosAIは原本を持たない一方、Object Store正本を保持と記述 | 顧客システムをsource of truthとし、取り込み時は正本性と保持条件を明記 |
| tokenization | データ本体、権利、状態、ブロックチェーン的表現が混在 | 権利・状態・条件・履歴のmachine-readable registryを基本定義 |
| 汎用モデル | 必然的終点、1T級目標、条件付き選択肢が混在 | 汎用化は5ゲートを通る選択肢。単一モデルを必達としない |
| 専用半導体 | 国家戦略の必然と、go/no-goオプションが混在 | go/no-go付き。既存アクセラレータ経路を常に維持 |
| CXL等の標準 | 特定規格・世代を正準アンカー化 | 技術候補へ格下げし、Architecture Gateで選定 |
| 日本のAI規制 | 「国際的に最も緩い」と断定 | 比較断定を削除し、学習・更新・実行統治の制度ギャップ評価へ変更 |
| 数値KPI | パラメータ数、GPU数、PoC数が前面 | 主権、業務outcome、安全性、更新時間、効率を主要KPI化 |

## 3. 文書別レビュー

### 3-1. `KairosAI-Strategy-Narrative-v2.21.md`

**評価**: 七文書中で最も包括的であり、正本の骨格として採用した。

**採用した中核**

- 重点六領域
- 三本柱
- 共有コア＋領域専門家＋拠点ローカル層
- AとCによるデータ共同生産
- knowledge placement
- 評価・署名・配備・rollback
- 汎用化と専用HWのgo/no-go

**修正した点**

- Site Computeと国家規模GPU表が同じPhaseに混在
- 電力を効率だけで解く記述がShared Computeには不足
- 技術規格や製品世代の固定が戦略正本として細かすぎる
- Phaseと投資額が確定計画のように読める
- 政策提言内の一部比較断定に根拠更新リスクがある
- 「実行基盤」「計算基盤」等が文章中で重複表現になっている箇所がある

**今後の位置づけ**: 本書への移行後は、詳細戦略解説版として改訂する。

### 3-2. `KairosAI-Empathy-Narrative-v1.md`

**評価**: 危機を生活者の視点へ翻訳する力が強い。政策説明資料として価値が高い。

**採用した中核**

- 判断OSだけでなく校正データが失われる
- 正常運用の蓄積が外部学習を強める
- 永続記憶により未来の判断ループが外部化する
- 2031〜2032年の仮想シナリオ

**修正した点**

- 仮想シナリオと政策確定事項を分離
- 70B、670B、1T等を必達ロードマップから外す
- L1公共保有・L2〜L4顧客所有の一律ルールを外す
- SPC、Fusion Core、BOTの事業仮説を正準戦略から外す
- 「12〜18か月で窓が閉じる」等の期限断定を計画リスク表現へ変更

**今後の位置づけ**: 共感・政策コミュニケーション用の派生資料。

### 3-3. `KairosAI-Implementation-Mechanism-v1.md`

**評価**: 重点領域、インフラ、事業化を一冊にまとめようとした点は有用。ただし、現行本編との版ずれが最も大きい。

**主な問題**

- 本編を正本と明記しながら、本編で除去済みのSPC/Fusion Marketを「本編出典」として記載
- 実在しない現行節番号への参照がある
- 電力調達路線がv2.21の効率路線と不整合
- 670B MoE自前学習等が確定計画として強すぎる
- 3層事業モデルの「Layer 1」がモデル層のLayer 1と衝突

**正本への反映**

- 需要形成、現場確保、案件化の考え方を採用
- SPC、BOT、Fusion Marketは事業仮説へ移動
- 事業レイヤーの番号表現を不採用

**今後の位置づけ**: `Business & Delivery Options`として再構成する。

### 3-4. `KairosAI-Onprem-Pillar-C-Physical-v0.1.md`

**評価**: 柱Cを物理構成へ落とした重要な技術別紙。ゾーン分離、Profile、基幹系境界は採用価値が高い。

**採用した中核**

- 基幹系を置き換えない
- read-only参照を基本とする
- write-backはpolicyとhuman reviewを通す
- GPU/App/Data/Integrationのゾーン分離
- state/policy/provenance/settlementの物理マッピング
- Profile別の段階導入

**修正した点**

- 「原本を持たない」と「Object Store正本」が衝突
- KG/KV/原本をCXLで一体保持する記述が必須要件として強すぎる
- H100はPhase 3以降等の製品固定がProfile設計と混在

**正本での解決**

- 顧客基幹系をsource of truthとする
- 証跡やスナップショットの取り込みは個別ポリシーで定義
- CXLは候補技術とする

**今後の位置づけ**: 技術別紙として継続し、正本の用語へ更新する。

### 3-5. `KairosAI-Pillars-Phases-Map-v0.1.md`

**評価**: 柱とPhaseの混同、Layer 1の多義性を発見した点が非常に有用。

**採用した中核**

- 柱は「何を」、Phaseは「いつ」
- 三柱は並行ワークストリーム
- AとCがデータを共同生産
- Phase 1のテレメトリが将来HW要件を定義

**修正した点**

- 3 Phase表を4 Phase正本へ統合
- 「A→B→Cが因果の必然」という一方向表現を、相互フィードバックへ修正
- 資産Layer 1の呼称を廃止

**今後の位置づけ**: 用語・責任マップの派生資料。

### 3-6. `KairosAI-Policy-Recommendation-v0.1.md`

**評価**: 政策メッセージへの圧縮は適切であり、正本の政策章へ多くを採用した。

**採用した中核**

- 政府の役割を資金・規制・調達・国家プログラム連携に整理
- 各柱の政策要求
- registry / policy / provenance / settlementの標準化

**修正した点**

- 「電力は効率のみ」で解く表現を二スコープへ修正
- AI規制の国際比較断定を削除
- Phase期間を統一
- 汎用モデルを最終必達点としない

**今後の位置づけ**: 省庁別の短縮版として更新する。

### 3-7. `KairosAI-Power-Sovereignty-v1.md`

**評価**: 戦略本編で弱くなっていた国家規模計算の物理条件を補う重要文書。

**採用した中核**

- 電力の量・質・時間の三要件
- 立地、系統、電源構成を同時設計する必要
- 電力計画は計算基盤より先行して着手が必要
- AI需要を長期電源投資の需要家として捉える視点

**修正した点**

- 顧客オンプレと国家規模クラスタを分離
- 特定地域・電源・設備数を正本で固定しない
- 地熱・原子力等の数値は更新頻度が高いため、Fact Sheet管理へ移す
- 共感ナラティブ旧版の系統運用シナリオとの参照ずれを正準から除外

**今後の位置づけ**: Shared Sovereign Computeの電力・立地別紙。

## 5. 外部ファクトの扱い

今回のレビューは七文書間の論理整合を対象とし、外部事実の再検証は行っていない。

次は変動が大きいため、戦略正本ではなく日付付きFact Sheetで管理すべきである。

- GPU、モデル、ライセンス、性能、価格
- CXL等の標準仕様と製品化時期
- 国内外のAI投資額
- GENIAC、ABCI等の予算・進捗
- 電力需要、系統容量、接続待ち
- 原子力、地熱、洋上風力等の設備・目標
- ラピダス、JASM等の量産時期とprocess node
- 各国のAI・データ規制比較
- 学習コストと所要日数

Fact Sheetには、基準日、一次出典、確認者、次回確認日を付す。

## 7. 最終判断

既存文書を単純に連結すると、戦略が広がる一方で、実装主体が「何を確定事項として動けばよいか」が曖昧になる。

今回の統合では、正本を次の一文へ収束させた。

> **重点領域の現場で、柱Aと柱Cが主権的な判断・実行データを共同生産し、柱Bがそれを境界内で効率的に動かす。蓄積した権利処理済み資産をもとに、共有コア、大規模計算、専用HWへ段階的かつゲート付きで進む。**

この一文から外れるモデル規模、技術規格、法人構造、投資額は、正本ではなく更新可能な計画仮説として扱う。
