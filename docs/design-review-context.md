# Design Review Context

このリポジトリでは、Figmaレビュー時に次の観点を優先する。

## 目的

- 松田総一氏のサイトを、深い技術知見と経営支援の両方が伝わるプロフィールサイトとして見せる
- 「何者か」より先に、「今どんな価値を提供できるか」が伝わることを重視する
- デザインは派手さよりも、信頼感、知性、深度、整理された印象を優先する

## 現在のビジュアル言語

- 背景は深いネイビー基調
- アクセントはアンバー系とシアン系
- 表示フォントは `Space Grotesk`
- 強調用のセリフは `Cormorant Garamond`
- 日本語本文は `Noto Sans JP`
- 丸みのあるカード、ガラス感のある濃色面、広めの余白を使う

## 構成上の優先順位

1. ヒーローで肩書きと価値を即時理解できること
2. 実績数値が信頼の補強として機能すること
3. Profile で技術と経営の両面経験が自然につながること
4. Focus で支援テーマが具体的に見えること
5. Results で公開実績が読みやすく整理されていること
6. Contact までの流れが重すぎず自然であること

## レビュー時のチェック項目

- 情報階層が一目で分かるか
- CTA が埋もれていないか
- 数値や肩書きが強すぎて本文が読みにくくなっていないか
- 日本語と英語の切り替えが不自然でないか
- モバイルでカードや見出しが詰まりすぎていないか
- ダークトーンの中で本文コントラストが不足していないか
- 装飾が増えすぎて、専門家としての落ち着きを損ねていないか

## Codex に依頼するときの形

- Figma の URL と `node-id` を渡す
- 必要なら「現状サイトと比較して」「モバイル中心で」「実装まで」などの条件を添える
- 例:
  - 「この Figma と現状実装の差分をレビューして」
  - 「この Figma をベースにトップだけ実装して」
  - 「モバイルで読みにくい箇所を洗い出して」

## 現在の制約

- この環境では、Figma の読み取りと比較レビューは可能
- 直接 Figma キャンバスを書き換える `use_figma` 相当のツールは現時点では見えていない
- そのため、必要に応じて以下のどちらかで進める
  - コード側を修正する
  - Figma 側の修正指示を具体的に書き出す
